# v0.6.4：文件处理恢复、三分区预览与随机关怀

发布日期：2026-10-26。

## 文件读取与修改

- 修复“读取文件技能 → 检查文件 → 提交修改”在第三步失去工具入口的问题；在原有四次工具执行预算内完成连续调用，保留停止与总时限。
- Office 参数不符合要求时返回具体字段错误，便于模型纠正。Excel 内置说明补齐完整的来源引用与精确修改示例。
- 模型把工具协议当成普通文字返回时，显示“文件操作没有执行”，不会据此执行操作或声称修改完成。旧消息仅调整显示，保留存储记录；代码块里的协议示例仍可阅读，语音不朗读泄露参数。
- 对已读完、模型总结失败的纯阅读任务，任务详情提供“重试总结”和“延长至 120 秒重试”。保留已提取内容、识别结果和分段笔记，只继续未完成总结；继续使用原任务的模型连接与思考档位。
- 延长等待只作用于本任务，不修改全局设置；重试由用户点击触发，不自动重发可能已经计费的请求。提交重试及真正开始总结前均核对来源版本和授权，重复请求、源文件变更或撤权会被拒绝。
- 文件读取完整与总结成功分别展示。新副本及原附件保留规则不变；普通阅读仍不自动保存 Markdown。

## 聊天与文件空间

- 移除聊天顶部的标题/模型栏和状态/工具/声音栏。设置集中在左侧“陪伴设置”；输入框原有按钮、窄屏导航及声音控制继续可用。
- 桌面放大预览后仍保留左侧导航、中间聊天和右侧预览。分隔线可双向拖动，让聊天或预览逐步收缩到被另一侧覆盖；端点保留展开按钮和键盘恢复路径。
- 收缩不卸载聊天和文件内容，保留输入草稿、批注、资源标签及阅读位置。恢复采用收缩前的宽度，不停留在拖动途中极窄的比例。
- 表格使用面板剩余高度，收紧标题、标签与工作表选择，取消原有 `60vh` 限高。合理列宽配合横向滚动，减少中文挤成竖列；范围说明按需展开。
- 表格继续采用单元格/文字批注后由小光生成修订副本，本版没有新增直接手工编辑单元格的编辑器。

## 关怀提醒

- 随机选择休息、护眼、喝水、活动和放松心绪等主题，避开近期主题与文案。
- 有效的新天气约以 20% 概率参与提醒，天气主题不会连续出现。没有有效天气时继续日常关怀，不为每次提醒额外调用模型。
- 天气使用“静观天象”“留意天色”等自然措辞，事实仍来自实际工具结果；提醒横幅不再显示数据时间和来源链接。
- 原有间隔、安静时段、暂停、语音开关及前台轮询规则保持不变。

## 验证与使用

- 后端全量回归 391 项通过、21 项跳过；前端 127 项通过。类型、ESLint、Prettier、Ruff 项目源码检查、OpenAPI 契约及生产构建通过。
- 本地公开副本从自己的目录实际导入代码，后端 390 项通过、22 项跳过，Ruff 与契约检查通过；多跳过一项项目内 LibreOffice 探针，公开代码不捆绑本机引擎。相关前端源码、包配置及锁文件与已验证源码一致。
- 使用合成表决票经过真实聊天工具链生成 `.xlsx` 修订副本，检查左右票区姓名清空、标题与字体保留、原附件字节不变。
- Windows 应用内浏览器检查 1280×792、1409×871 桌面及 390×844 窄屏，实际覆盖分隔线双向拖动、端点恢复、草稿/批注保留、宽表横纵滚动、设置入口与关怀提醒。
- 隔离浏览器使用真实的合成 22 页 PDF 提取内容，以替代模型模拟总结超时和恢复。没有重放用户原任务，没有调用真实付费模型、TTS 或 ASR；测试通过不代表真实 MiMo 上游已验证，延长等待也不保证外部服务一定完成。
- 未做真机手机、多浏览器兼容性或性能压测；现有 PDF.js、选择控件和构建分包提示仍存在，不影响本轮通过结果。

已运行的旧后端需要正常关闭并重新使用 `Start_up.bat` 启动，再刷新页面，才能加载本版后端逻辑。升级不会自动重放旧失败任务；PDF 可从“状态与操作”主动重试，未执行的表格请求可重新发送。

本版不安装新依赖、不更改私人模型设置，不包含用户聊天、附件、日志或验收数据。只同步相关源码、测试、契约与版本说明到本地公开副本，由维护者使用 GitHub Desktop 自行提交上传。
