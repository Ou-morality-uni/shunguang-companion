# v0.7.3：QQ 场景档案与精简控制面板

在 QQ 接入面板给私聊、群及每位群成员手动填写称呼、背景和记忆；同一个 QQ 在不同场景分别管理。手动资料不被自动记忆改写，Windows 与 Linux 轻量服务器共用实现。

## 使用

1. 正常停止旧后端，运行 Start_up.bat 加载本版，刷新网页。依赖不变；旧 QQ 数据库兼容增加档案和摘要修订字段，不清空记录。
2. “QQ 接入 → 聊天管理”选择联系人／群。“消息”查看记录，“资料与记忆”填写档案，“设置”管理采集、聊天、图片与表情。
3. 群资料下点击“成员”，搜索昵称、群名片或 QQ 号；桥接离线仍可用已知名单或输入 QQ 号提前建档。
4. 称呼、别名直接填写；其余常用字段在“更多资料”，另可增删自定义记忆。每条群成员资料可选“本群可用／仅回复该成员”，保存后用于下一次回复。
5. “群摘要”沿用当前群，统一设置定时、手动窗口与投递去向，并查看历史结果。

“仅回复该成员”仍是群内公开回复，不等于保密私聊。群摘要只使用群资料与相关的本群可用条目；档案不证明历史发生过某事。主人手动 QQ 档案不进入 Web，原有共享的自动私人记忆继续保留。

## 改进与保护

- QQ 主入口从六项归并为连接、聊天管理、群摘要；桌面使用列表与详情两栏，手机逐层进入／返回。切换栏目保留聊天对象，成员返回保留搜索分页。
- 手动与自动记忆分区标注。固定字段可留空，常用称呼优先展示，自定义条目可编辑删除，范围紧邻内容；保存失败保留草稿，切换时提醒未保存变化。
- 按机器人、场景和 QQ 号隔离；并发编辑使用修订检查，冲突不静默覆盖。删除档案不影响自动事实或聊天，采集到期清理也不删除手动资料。
- 按需读取并缓存成员名单，校验桥接数据；失败保留名单及档案。建档和读取名单不会自动开启采集、回复或投递。
- 限制单项、总量和每轮上下文预算，只注入允许使用的相关资料；不以档案文字赋予主人身份或工具权限。直接提取、记忆工具和后台候选校验会排除明确的临时称呼。
- 生成中和待投递阶段复查资料修订，资料变化会拦住旧回复／摘要，提示重新生成；已发送的历史不自动改写，不能撤回已经提交给模型的输入。
- 档案与成员缓存属于私人 data/qq，随原有私有备份保存，不进入源码分发或公开副本。未增加依赖或服务器向量模型。

详细操作见 [QQ 接入指南](../../docs/qq-setup.md)，Linux 升级见 [服务器部署指南](../../docs/server-deployment.md)。主 README 的安装正文沿用原流程。
