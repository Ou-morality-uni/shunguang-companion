## 安装选择与环境保留

- 继续双击 `Install.bat` 安装、`Start_up.bat` 启动。Node.js 仍要求 24；Python 和 Node.js 均由用户事先安装。
- 安装器通过已有项目环境、Python launcher 和 PATH 发现真实解释器，检查版本、架构、实现、稳定状态及自由线程标记。首次安装优先选择电脑已有的较新受支持版本。
- 已有有效的 `.venv`／`.venv-rag` 优先复用，不会因为系统装了新版 Python 就自动迁移。不删除旧环境或用户数据，不改变系统默认 Python、PATH 或注册表。
- 支持显式指定解释器；指定版本与已有环境冲突、双环境版本不一致或环境不完整时，先停止并说明，不混用 pip 安装依赖。
- 修复旧 PowerShell 入口忽略未知参数的问题；误传参数时拒绝执行。新增无安装副作用的解释器检查入口。

只查看当前选择，不安装依赖：

```powershell
.\Install.bat -CheckPython
```

在首次安装时指定解释器：

```powershell
.\Install.bat -PythonPath "D:\Python314\python.exe"
```

以上路径为示例，替换为自己电脑的 `python.exe`。仅重装检索依赖的 `scripts/install-rag.ps1` 同样支持 `-PythonPath` 和 `-CheckPython`。

## 升级及切换 Python

已有 3.11 环境不必切换，可关闭后端后重新运行 `Install.bat` 更新依赖；`data/` 下的聊天、配置、附件和成果继续保留。

如果主动切换到另一 Python 小版本，先停止后端，保存必要备份，将根目录 `.venv`、`.venv-rag` 分别改名保留，再用 `-PythonPath` 重新安装。不要只重建其中一个环境，不要移动或删除 `data/` 和模型目录。确认新环境完整安装、检索和聊天可用后，再自行处理旧环境。安装器不会替用户删除旧环境。

不支持 Python 3.15、预发布版、自由线程版、PyPy、32 位或 ARM64 的一键安装；本版只承诺常规 CPython 3.11～3.14、Windows 10/11 x64。建议使用各分支较新的稳定补丁版；未来版本需另行验证，不作永久兼容保证。

### 同版本工作流修复

修复两条含 `--only-binary=:all:` 的安装命令在 YAML 普通字符串末尾出现冒号、导致 GitHub 拒绝加载工作流的问题。命令改为 YAML 块字符串，实际安装参数保持不变。新增工作流解析回归检查，并在本地源码与公开副本验证；此前业务测试通过不代表工作流文件本身已经通过 GitHub 解析。此修复保留版本号 0.6.3，远端结果以推送修复后新触发的 Actions 为准。

### 2026-10-26：检索 CI 环境隔离修复

维护者推送后的 [Verify #19](https://github.com/Ou-morality-uni/shunguang-companion/actions/runs/40208643902) 中，Windows／Ubuntu 的八个后端任务、前端及检索 3.11／3.13／3.14 均通过；检索 3.12 在 `pip check` 失败。实际日志显示运行器预装的 `pipx 1.18.4` 要求 `filelock>=4.2`，与项目锁定的 `filelock==3.32.3` 冲突。

检索任务现在先创建独立 `.venv-rag`，随后安装、`pip check` 和 CPU 计算均显式使用该环境的 Python，与项目安装器保持一致。项目依赖版本不变，保留依赖一致性检查。新增带冲突预装包元数据的回归：先实际复现同一条 `pip check` 错误，再执行工作流中的环境创建和检查命令，确认隔离后通过；该测试不下载或执行 pipx。

本机 Python 3.12 已完整执行真实工作流的环境创建、CPU PyTorch 与锁定检索依赖安装、`pip check`、导入与 CPU 计算，全部通过；外层预装包冲突仍存在，仅检索环境被隔离。工作流回归共 2 项通过。本次继续保留 0.6.3。修复后的远端结果须在维护者提交并推送本地公开副本后确认，不将本地回归结果当作新一轮 GitHub Actions 已通过。
