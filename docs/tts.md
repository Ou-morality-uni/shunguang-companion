# TTS 接入与选型

更新：2026-10-17，v0.1.5 维护修订。

## 支持范围

只保留小米 MiMo 与阿里云百炼。火山入口与适配已停用；旧火山配置加载为禁用状态，不复用其密钥。

| 方案 | 模型与协议 | 参考录音与后续调用 |
| --- | --- | --- |
| 小米 MiMo | `mimo-v2.5-tts-voiceclone`；分段非流式 | 填运行后端电脑上的 MP3/WAV 路径。每次合成提交参考声音，编码缓存在内存，不复制原录音。 |
| 百炼 Qwen-Audio-TTS | 默认 `qwen-audio-3.1-tts-flash`；另适配 `qwen-audio-3.0-tts-flash`、`qwen-audio-3.0-tts-plus`；inference WebSocket | 创建云端音色后凭 ID 合成，之后不再读取原 MP3。 |
| 百炼旧 Qwen-TTS | `qwen3-tts-vc-realtime-2026-01-15` 等旧配置；realtime WebSocket | 保留兼容；实际可用性以账号、地域与模型检查为准。旧音色不能直接跨用至 Qwen-Audio。 |

语音模型预设表示项目已实现协议，不代表账号权限验证。模型广场可见与 API Key 可调用是两件事。

## 百炼：一次创建，后续复用

1. 打开“陪伴设置 → 声音与播放”，选择百炼，填写官方地址、该地域专用密钥与模型并保存。
2. 点击“检查百炼连接”。这只是连接检查，明确不代表模型和音色已通过合成验收；可用性以短句试听为准。
3. 允许参考音频外部处理并保存。填写音色名称，从浏览器临时选择 MP3，或填写服务电脑上的录音路径。点击“创建并保存云端音色”才上传样本。
4. 项目保存并选择返回的音色 ID。刷新列表可看到多个音色、名称、模型与审核状态；处理中的音色等待审核通过后再选择使用。可以复制 ID、选择保存、用语音测试试听、确认删除。
5. 后续对话只发送待合成文字与音色 ID。原 MP3 移走不会影响已经创建且有效的百炼音色；小米仍需要原文件。

Qwen-Audio 的创建接口只接受 URL。项目通过百炼官方私有临时上传机制将本次样本转换为模型绑定的 `oss://` URL，再创建音色；不要求额外提供 OSS 长期密钥，也不建立本地 reference 归档。临时录音有效期 48 小时，音色 ID 与临时 URL 分开管理。此机制用于低频创建；批量生产场景需另行设计稳定存储。旧 Qwen-TTS 创建则使用 Base64，字段与协议分别处理。

北京地址：`https://dashscope.aliyuncs.com`；新加坡：`https://dashscope-intl.aliyuncs.com`。也接受官方业务空间专属域名，例如 `https://实际WorkspaceId.cn-beijing.maas.aliyuncs.com`。不要把聊天中转站的密钥填到百炼官方接口。更换账号、地域或模型后必须重新核对音色，不能仅沿用旧 ID。

音色创建与合成可能分别收费，使用前以对应模型的实时价格为准。项目不购买音色槽位或订阅，不自动重复付费创建；但不保证厂商未来计费政策不变。创建超时后先刷新云端列表核实，避免重复扣费。云端成功而本机保存失败时会提示可恢复的 ID。

## 小米：只引用路径

填写相对于项目根目录的路径，或运行后端电脑上的绝对路径。点击验证仅检查文件，不创建参考目录和索引。手机浏览器无法向后端提供手机文件的真实本机路径；百炼可以临时选文件创建，小米需要先把录音放到服务电脑上再填路径。

开启外部参考处理后才发送样本。小米合并短句并串行合成，降低并发与短请求引起的限流；这不能保证消除厂商限流。HTTP 429 表示请求受限，需进一步核对频率和额度，不再直接判定余额不足。

## 播放、诊断与验证边界

百炼 Qwen-Audio 3.1/3.0 自动朗读采用持续文本输入：一次回复只开启一个上游任务，文字生成时通过同一 WebSocket 追加，音频同时返回。文本优先积累约40字并在语句边界提交，短句或未完成片段最多等待600ms便追加，避免逐字请求或长时间等全文。上游会缓存不完整语句，不能保证未形成完整语句时立即发声。回复完成后发送一次结束事件；手动播放仍整条提交。旧 Qwen3 兼容模型保留等待全文的方式，小米不变。

浏览器对持续输入模式使用约350ms音频预缓冲，后续PCM按音频时钟连续排程；正常有余量时直接衔接，断粮后重新积累小缓冲。短回复在任务完成时立即释放尾部，不必凑满缓冲。该策略减少网络小幅波动和重复建立任务造成的断续；若模型文字生成过慢、网络中断或上游合成停顿，仍可能出现等待。它不是语音全程零停顿保证。

百炼沿用项目每条回复累计最多3000个Unicode字符的限制；持续输入中超过限制会停止余下朗读并提示，已说出的内容无法撤回，不会自动另开任务。该数值是项目边界，不是厂商全部模型能力的声明。只有文本正常结束且上游确认完整成功后才保存WAV供重播；断流、取消或失败不缓存残缺成品。停止、切换会话、配置变化和新回复会关闭旧连接并停止已排程音频，不会自动重试可能已经计费的任务。

界面“首音约”从提交/点击计时至浏览器开始播放或排程，包含文字生成、文本预缓冲、网络、合成及音频缓冲，不等同于厂商纯推理延迟。没有进行同录音、同文本的双厂商音质盲测，不声称哪家效果绝对最好。

### 持续输入接入依据与边界

依据官方WebSocket接入与客户端事件规范，同一任务的run-task、多个continue-task、finish-task使用同一task_id；必须等task-started再发文字，最后等待task-finished。官方文本间隔上限为23秒，本项目在等待下一段输入18秒时结束异常连接，明确提示，不发送虚假文字或自动重新计费。后台总超时仍受语音设置约束。连接复用于本轮，不跨轮共享任务。

新增`/api/tts/live`只代理当前已保存的百炼Qwen-Audio设置，不从浏览器接收厂商密钥；显式复用既有Host、Origin、本机来源与局域网Cookie验证。开发模式Vite转发WebSocket；若另加反向代理，也须允许WebSocket升级。既有HTTP合成和SSE接口保留。

2026-10-17用当前账号及已有克隆音色完成一次短句真实验收：文字未提交完前已收到PCM，单一上游任务，首段PCM约1.285秒，返回音频5.51秒；此计时不包含大语言模型生成或浏览器播放缓冲，也不是通用延迟承诺。本次没有重新创建音色，未做主观盲听或长期网络可用率测量。

故障会区分认证、权限、限流、模型/音色拒绝、连接和不完整音频，不向浏览器返回上游原始错误或密钥。公共列表和协议单元测试通过不等于真实账户端到端合成通过；每个使用者仍需保存自己的配置并执行一次试听。

## 模块边界

- `voice.py`：源文件验证、原始 MiMo 适配、合成音频缓存与安全传输。
- `tts_providers.py`：统一流接口、旧 Qwen realtime 协议、模型预检与新协议选择。
- `aliyun_audio.py`：Qwen-Audio inference 协议与百炼私有临时上传。
- `cloud_voices.py`：音色列表、创建记录、去重、选择、删除及账号/模型隔离。
- `CloudVoiceManager.tsx`：网页音色管理；`useAudioQueue.tsx`：播放与取消。

持续输入回归覆盖同任务追加、首段提前返回、完整缓存、取消关闭上游、累计长度、跨站拒绝及局域网会话；前端验证单连接、文本/音频预缓冲、短尾释放、连续排程与设置变更取消，并保留手动整条播放和旧模型兼容用例。
