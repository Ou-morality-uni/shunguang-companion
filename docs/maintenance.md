# 维护与扩展

2026-10-15 工程改造。本版本更新见 [v0.1.5 更新说明](../RELEASE_NOTES_v0.1.5.md)。本文说明模块边界、开发流程及评审取舍。

## 代码边界

| 位置 | 职责与扩展方式 |
| --- | --- |
| `backend/app/main.py` | 应用组装、启动、统一异常处理、访问保护及静态文件。新增业务不继续堆在入口文件。 |
| `backend/app/routes/` | 设置/提供商、聊天、记忆、检索与资源接口。新领域新增 router，并在入口注册。 |
| `backend/app/runtime.py` | 单 worker 运行状态、Store 实例、对话互斥与停止完成信号。进程状态不是持久数据。 |
| `backend/app/store.py` / `migrations.py` | 数据读写和有序迁移。业务模块不直接执行 SQL。 |
| `backend/app/schemas.py` | 核心响应契约；接口变更先更新模型，再生成前端类型。 |
| `backend/app/llm.py` / `anthropic_adapter.py` | 模型与协议适配；保持 UI 配置、零自动重试、不上传云端追踪的约定。 |
| `frontend/src/useConversation.ts` | 会话选择、历史、发送/停止/删除及临时流式状态。 |
| `frontend/src/sse.ts` / `api.ts` | 流协议解析和 HTTP 传输；不依赖页面布局。 |
| `frontend/src/ConversationHistory.tsx` | 会话列表及删除确认。 |
| `frontend/src/generated/` | 自动生成的核心类型与输入长度限制；不要手工修改。 |

`services.py` 的语音、工具和提醒路由继续复用公共访问保护。检索继续使用现有模型；语音新增多厂商适配，见 [TTS 接入与选型](tts.md)。

## 开发检查

使用 Python 3.11+、Node.js 22。在项目根目录、激活虚拟环境后运行：

```sh
python -m pip install -r backend/requirements-dev.txt
npm --prefix frontend ci
python scripts/dev.py verify
```

`verify` 检查后端测试、Ruff、格式、OpenAPI 是否过期，以及前端类型、lint、格式、测试、生产构建。`serve` 本机启动；`test` 运行后端测试；`build` 构建前端。

接口变更后执行 `python scripts/dev.py contracts`，将 `frontend/openapi.json` 与 `frontend/src/generated/` 一起纳入版本控制。导出不启动应用生命周期，不访问用户数据库。CI 会检查后端契约及 TypeScript 生成结果有无漂移。SSE 使用相同的消息结构，分帧和中断另有测试。

生产安装仅使用 `backend/requirements.lock.txt`，不安装 pytest/Ruff。新依赖需要同时更新声明和锁文件。GitHub Actions 已配置 Windows/Linux 后端及前端检查；只有远端运行结果才能称为 CI 已通过。

## 数据与兼容约定

- 局域网访问保护返回 HTTP 401 时，携带 `code: lan_auth_required`。前端普通请求、聊天和语音流只根据此标记弹出访问口令框；上游密钥无效的 HTTP 401 保留为业务错误，不要求用户登录，也不清除本机会话。
- 启动时将无版本旧库逐步升级至版本 3。旧消息顺序及元数据保留；新增显式 `seq`，支持 `limit/before` 分页。迁移前使用 SQLite 在线备份接口生成 `data/backups/*-vN-*.sqlite3`；迁移事务失败会回滚，遇到更高版本拒绝降级。
- 新建页面不写库。首条用户消息与新会话同事务落库；配置和模型构建失败不创建会话。旧 `POST /api/conversations` 暂保留供已有客户端使用。
- 回复期间禁止删除同一会话。停止接口成功意味着最终记录已提交；落库失败或等待超时返回明确错误。客户端不制造历史消息、不用延迟轮询猜测落库时间。
- 删除会话级联删除消息及候选记忆；已确认的事实保留，来源标识清空。长期事实由记忆空间另行删除。自动迁移备份仍包含迁移时的历史，删除会话不会改写备份。
- Windows 继续使用用户级 DPAPI，旧密文无需手动迁移。新密文带后端/版本前缀；非 Windows 使用系统密钥环中的主密钥加密设置中的凭据。仅允许系统 vault，缺失服务就失败，不回退为明文或同目录密钥文件。换机仍需重新填写密钥。
- 仍要求单 worker。扩大到多 worker 前必须把运行中任务、停止信号、限流和会话互斥移到共享协调层；WAL 本身不能解决这些问题。
- 应用日志只记录操作名、异常类型、数字状态码；不记录密钥、正文、请求地址、异常全文或堆栈局部变量。

## 对评审建议的取舍

| 建议 | 处理 |
| --- | --- |
| 日志、质量工具、开发依赖拆分、CI | 已落实；使用字段白名单，避免报告示例中的完整异常堆栈泄露。 |
| 空会话、删除、迁移、同步 I/O、接口类型 | 已落实核心路径；聊天数据库/配置/提示词读写移出事件循环。 |

| 旧入口、错误 manifest、静态资料清单 | 报告基于旧快照。现项目旧入口已归档、世界档案已改为运行时 RAG，不重复改造。 |

## 下一步技术债与验收条件

1. 前端长历史增量加载：后端游标接口已具备；验收需万条消息下首屏耗时、滚动位置、连续分页无重复/遗漏。
2. 扩展功能契约：语音/工具动态 payload 仍保留部分手写类型；逐域补明确响应模型，并纳入生成流程。
3. 设置页进一步拆分：当前已格式化，后续按提供商、语音、提醒分组件，避免新增功能继续扩大单组件。
4. 公网部署：需独立的 HTTPS、鉴权、请求配额、凭据注入及运维方案；不直接暴露当前本机服务。
5. 系统密钥环实机验收：分别验证 macOS Keychain、Linux Secret Service/KWallet 的保存、重启、清除和账户变更。无桌面会话的 Linux 容器暂不承诺可用。
6. 数据备份管理：补用户可见的备份列表、保留期限和删除能力；当前自动备份保留在本机，恢复需停止服务并使用对应版本。

本次测试使用临时数据库、替身模型和模拟外部服务，不将此结果当成真实云模型、GPU 检索或语音服务的重新验收。


## 2026-10-16：记忆、检索、工具与云端音色修订

继续沿用现有路由、Store、SQLite 和前端架构，未切换框架或改写检索索引。

- `memory.py` 负责明确自述提取、当前消息证据验证、事实操作工具、预算召回。`Store` 负责事务、事实更新、来源记录和历史召回。共享范围是同一服务数据目录；没有新增多用户隔离或跨电脑同步。
- 数据库版本 3 增加记忆操作记录、忘记边界、来源消息屏蔽与会话摘要表。摘要目前是有来源 ID 的有限用户原文摘录，不是自动推断人格/情绪的模型总结，也不是独立任务调度器。
- “忘记”会移除长期事实并阻止已记录值和对应历史来源重新自动召回；原始聊天、操作记录和迁移备份仍可能保留。删除记忆不代表物理擦除全部聊天文件。删除会话仍遵循原有级联策略。
- `retrieval_router.py` 区分用户记忆、日常、实时工具与世界观问题，并在向量候选之后检查实体/主题。没有引入重排模型；保留候选、实际上下文、最终引用三个阶段的数据。只有回答中实际引用的条目显示为引用来源；这不是自动事实核查证明。
- `tools.py` 增加中文城市候选和行政区匹配，区分认证、权限、限流、额度、无结果和相关性不足。公开 HTML/RSS 搜索是尽力服务，不能保证外部入口永远可用。
- 百炼音色与模型协议见 [TTS 文档](tts.md)。本地 `cloud-voices.json` 仅保存元数据；`tts-profiles.json` 分厂商保存加密配置，服务端不会把密钥返回浏览器。
- 本轮回归使用临时数据库验证自动记忆、跨聊天、忘记、角色数据隔离和取消。真实天气、搜索和语音验收另记；不得把浏览器替身回复称为真实角色质量测试。
