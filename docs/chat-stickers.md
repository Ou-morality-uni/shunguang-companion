# 聊天表情附件

每条新完成的角色回复附一张表情，优先保持语境，再避免重复；找不到匹配时使用中性陪伴图。当前自动选择范围是 44 张红色人格表情，包含新增的 30 张日常表情。白色人格图片保留在原资源目录，不进入自动兜底池。

## 工作流程

1. `backend/app/stickers.py` 从 `source/resources/character/stickers/reactions.json` 读取场景说明与图片白名单。图片缺失时跳过；清单无法读取时使用已有的三张通用陪伴图。
2. 聊天路由将场景选择规则加入原来的系统提示。模型结合当前用户消息、已有上下文和拟回复的态度，在最终回复开头输出 `[[sticker:场景]]`，随后自然回答。解析器也兼容标记出现在末尾的模型。没有新增模型调用，但会增加少量提示和输出 Token。
3. `ReplyDecoration` 在流式文本进入网页、语音队列和数据库之前移除标记，支持标记跨分片、无标记和不完整标记。不存在或未知的场景使用 `neutral`。这是模型在原回复中的语境判断，不是独立的情绪识别模型，也不能保证所有对话判断完全正确。
4. 服务端只从对应场景的本地红色图片中选择。优先避开最近三张；单个场景只有一张且上次刚用过时，改用中性图，避免为去重而换成相反情绪。选择结果保存在现有消息 `metadata.sticker` 中，无需数据库结构迁移。
5. `MessageOut.sticker` 同时随 SSE 完成事件和历史消息返回。前端 `MessageSticker` 在正文下方显示一张约 160px 的图片，不进入复制和 TTS 文本。图片加载失败时依次使用中性本地图片，全部缺失才降级为陪伴文字，不循环重试外链。

中性池为“你说，我听着”“陪你坐会儿”“在呢，陪着你”。它们不以大笑、庆祝或嘲讽作为兜底。流式回复完成前、停止或失败的回复不追加表情。旧历史不回填图片；新增回复刷新、翻页、重启后保留原选择。

## 增加或调整图片

把已确认的人格图片放入原 `stickers/` 目录，然后在 `reactions.json` 的 `items` 中登记唯一 `id`、文件名、文字说明、`persona: red` 和适用的 `scenes`。新场景同时加入顶层 `scenes` 并写清适用语境。路径只允许当前目录的 PNG 文件，不接受模型生成的路径或远程链接。新增图片本身不会未经标注自动投入选择，避免误发白色人格或不合语境的图片。

`daily-index.json` 继续记录日常图片与字幕；`reactions.json` 负责运行时选择，两者职责不同。修改后运行后端表情/聊天测试、导出接口契约、生成前端类型并执行前端检查。发布时同步代码、契约、清单与对应图片，不复制个人 `data/`。

## 本轮验证

后端完整回归 147 项通过、1 项可选检索测试跳过，前端 33 项通过，类型、lint、格式、契约和生产构建检查通过。浏览器核对真实表情组件在桌面与 390px 容器内的加载和布局；该预览只含构造内容，不读取配置或聊天。

对当前 `mimo-v2.6-flash` 做了四次构造短对话请求：庆祝场景返回有效场景标记；安慰场景最初两次省略标记时触发中性兜底，改为先输出协议标记后复核得到 `comfort` 和“陪你坐会儿”。这是有限样本，不代表所有模型和对话都能正确判断情绪。运行时不会为漏标记额外调用或重试模型。
