# QQ 可选接入指南

普通 Web 聊天无需 QQ。首次运行 Start_up.bat 可选“暂不接入”，不会下载 NapCat；以后停止后端，运行 `Start_up.bat -Setup` 可重新查看接入指南。完整／轻量安装均可接 QQ。

## 使用前说明

NapCat 是第三方桥接，并非腾讯官方机器人接入；协议变化、平台规则和账户风控可能导致掉线或限制，不保证持续可用或不受限。使用自己的账号，了解并遵守平台规则和群成员的隐私约定。不要公开聊天记录、登录状态、Token、绑定码或整个 data 文件夹。模型、图片识别和定时摘要会将必要内容提交给你选定的外部模型，可能产生费用。只为确有需要的联系人或群开启权限。

## Windows

1. 双击 Start_up.bat 完成安装，在网页配置自己的模型连接，确认 Web 能正常回复。
2. 阅读 [NapCat 官方 Shell 指南](https://napneko.github.io/guide/boot/Shell)，从官方发布入口选择 Windows 安装方式，解压到独立目录并按官方步骤运行、扫码登录。已有可用桥接可复用，不要重复安装或覆盖登录目录。Framework 用于已有相应桌面插件环境的使用者，不是新手必需项。
3. 在 NapCat 的网络配置中添加 **WebSocket 服务端（正向）**：监听 `127.0.0.1`，端口 `3001`，消息格式 `array`，启用；设置独立 Access Token，关闭自身消息上报。不要把 WebUI 登录 Token 误当 OneBot Token。
4. 打开叶瞬光“QQ 接入 → 连接”，填写机器人 QQ 号、`ws://127.0.0.1:3001`、相同 OneBot Token，选择回复模型，勾选启用并保存。查看连接状态；桥接未安装或离线不影响 Web 使用。
5. 如需绑定主人，生成一次性绑定码，从自己的 QQ 向机器人**私聊**发送页面给出的 `/绑定 一次性码`。不要发到群里；绑定码会过期，过期后重新生成。
6. 打开“聊天管理”，切换私聊／群聊并刷新列表，选择对象后在“设置”中开启采集和聊天。群默认关闭聊天，可按需选择仅被 @／指令触发或适度自然参与。图片识别须选视觉模型并单独授权；每个聊天可单独开关回复表情。
7. 同一对象的“消息”查看 QQ 聊天与投递状态，“资料与记忆”管理手动档案和自动记忆；“群摘要”管理摘要任务与结果。QQ 记录与 Web 最近对话分开；主人私聊继续共享私人自动记忆，其他私聊与群分别隔离。

## 给私聊、群聊和成员填写资料

1. “QQ 接入 → 聊天管理”选择联系人或群；没有历史时也可展开“按号码打开”，输入联系人 QQ 号或群号。先在连接页保存机器人 QQ 号即可建档，不要求启用连接。
2. 进入“资料与记忆”。私聊直接编辑个人档案；群聊可选择“群资料”，填写用途、共同背景、常用术语和摘要关注点。
3. 群内点击“成员”，按昵称、群名片或 QQ 号查找，再点开成员。首次按需读取桥接名单，短时复用缓存；失败会显示缓存、已采集和手动建档成员。也可直接输入 QQ 号给尚未发言的人提前建档，不代表机器人确认对方仍在群内。
4. 常用字段为称呼、别名；展开“更多资料”可填写身份／关系、兴趣偏好、交流偏好和长期事项。点击“新增记忆”可以填写标题与内容，支持删改；留空的常用字段不保存。
5. 群成员每条资料都可选择“本群可用”或“仅回复该成员”。新称呼默认本群可用，其他字段和自定义记忆默认仅回复本人；后续保存沿用你的选择。**仅回复该成员仍是群内公开回复，不是保密私聊。** 私聊与群本身的资料不需要额外选择范围。
6. 点击“保存资料”，看到成功提示后生效。切换对象或栏目会提醒未保存变化；多个窗口同时修改会提示冲突，保留当前草稿。需要核对最新值时先自行保留草稿，再点“重新读取”，不要盲目覆盖。

推荐填写稳定、必要且愿意用于当前聊天的信息，例如“称呼小林”“群内负责摄影”“回答简短一些”“正在准备某项考试”。不必填写真实姓名、住址、证件等无关资料。资料将随必要上下文提交给你选定的模型。

同一人在私聊与不同群的档案分别保存，不自动共享；主人新增手动 QQ 档案不进入 Web。自动记忆继续保存，不能自动改写手动档案；模型被要求优先使用手动值。本轮临时称呼不修改档案，也不存成永久称呼。自由文本冲突需在面板核对，下方展开“自动记忆与对话”可删除相冲突的自动事实。

档案不赋予“主人”身份、聊天或投递权限。删除手动条目不代表抹去历史发言或已经学到的独立事实，原有自动记忆须单独处理。原始消息到期或清理时手动资料保留；档案位于私人 `data/qq/qq.sqlite3`，随私有备份保存，勿上传 GitHub。单档案最多40项、每项2000字、合计12000字；模型每轮只使用相关且预算内的完整条目，不保证全部资料同时进入上下文。

保存、更正或收紧范围后，新回复使用新值；生成中或等待投递的旧结果会被拦住，需重新发起对话／生成摘要。已经发送的消息与历史摘要不自动改写，也不能撤回已提交给模型的输入。若多个消息片段中途发生修改，之前已发出的部分仍需在 QQ 中查看。

## 群摘要

在“群摘要”选择群，采集、聊天、摘要任务和摘要投递是独立权限。可以只采集并总结而不参与聊天。设置每日固定时间或间隔，选择自上次结束以来／固定时段；默认摘要仅保存在面板。私发主人或发回原群须单独开启；发群需要投递许可。只能总结实际采集到的消息，掉线期间的消息不保证自动补齐。

摘要只使用群资料和标为“本群可用”的相关成员条目，“仅回复该成员”的手动资料不进入摘要，即使只保存在面板或私发给主人。档案用于解释称呼与背景，不作为历史事件或新待办的证据；以当时已采集的发言为准。

## Linux

先按 [服务器部署指南](server-deployment.md) 启动 Web；服务器默认不启动桥接。自行按官方指南安装 NapCat，或明确选择包内可选桥接配置，完成扫码后按上面的 OneBot 设置连接。叶瞬光后端与桥接必须在同一服务器可访问的本机网络中。管理面板和 OneBot 端口保持 loopback，使用 SSH 隧道访问，不将管理端口直接开放公网。

## 排障

- 显示未启用：保存 Token、机器人号并勾选启用；端口可达不代表应用已保存连接。
- 连上却不回复时，在「聊天管理 → 消息 → 最新消息」查看最近一条消息的处理状态。如果仅采集，检查该聊天的回复开关和触发方式。模型失败时按显示的原因检查模型配置。没有记录时先检查 QQ 连接及该聊天的采集开关。
- 图片不识别：检查本联系人／群的视觉授权、选定模型是否支持图片，以及 QQ 采集记录中的失败状态。
- 表情发送：使用自带素材的 QQ 自定义图片表情方式，不是 QQ 商城表情，通常无需提前收藏；客户端显示需实际测试。
- 身份验证／风控：暂停桥接重复重连，使用官方 QQ 完成账户验证后再尝试，不使用所谓防封保证。
- 只关闭网页不会停止后台。Windows 后端窗口正常退出后才停止；服务器按部署指南维护服务。

本项目不自动购买服务、填写 API 或代替用户登录 QQ。QQ 语音回复尚未纳入此版。
